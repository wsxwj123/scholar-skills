## 一·补、完整调用示例（从 SKILL.md 下沉）

SKILL.md 正文只保留 init / sync-all / gate-check / merge / full-review 五条核心命令，以下为其余命令的完整 flag 形式，均从 proposal 项目根目录执行：

```
python scripts/state_manager.py --root . write-cycle --section P3_2 --token-budget 2000   # → P3_2_工作条件.md
python scripts/state_manager.py --root . write-cycle --section P3_3 --token-budget 1000   # → P3_3_正在承担的相关项目.md
python scripts/state_manager.py --root . write-cycle --section P3_4 --token-budget 1000   # → P3_4_完成基金项目情况.md
python scripts/state_manager.py --root . write-cycle --section P4   --token-budget 500    # → P4_其他需要说明的情况.md
python scripts/state_manager.py --root . page-estimate --sections-dir sections
python scripts/state_manager.py --root . word-count --sections-dir sections
```

**一致性校验：**
```
python scripts/consistency_mapper.py --path data/consistency_map.json validate            # 全量 V-01~V-12
python scripts/consistency_mapper.py --path data/consistency_map.json validate --phase 2   # 只算并只报该阶段应验规则集
python scripts/consistency_mapper.py --path data/consistency_map.json validate --rules V-01,V-02
python scripts/consistency_mapper.py --path data/consistency_map.json validate-one V-01
```
`--phase` 阶段→规则集映射（依据 SKILL.md「V 规则分层说明」）：
- `--phase 2` → V-01,V-02,V-03,V-04,V-05,V-08（H/O/RC/KSQ/IN 结构链路）
- `--phase 3` → Phase 2 集合 + V-12（M.alternative_plan，自 Phase 3 起 ERROR 硬门控）
- `--phase 7` → 全量 V-01~V-12

`--phase` 只计算且只输出对应规则，机制上避免 Phase 2 看到依赖 F/预算字段的 V-06/V-07/V-09/V-11 结论而误判。`--rules` 与 `--phase` 互斥。

**文献验证：**
```

python scripts/citation_validator.py verify-entry --index data/literature_index.json --p1 sections/P1_立项依据.md --ref-number 1 --mcp-cache data/mcp_literature_cache.json --require-mcp
python scripts/citation_validator.py matrix-check --p1 sections/P1_立项依据.md --index data/literature_index.json --ref sections/REF_参考文献.md
```

**评审与风格：**
```

python scripts/diagnosis_engine.py full-review --sections-dir sections --consistency data/consistency_map.json --index data/literature_index.json --p1 sections/P1_立项依据.md --ref sections/REF_参考文献.md --output data/diagnosis_report.json --root .
python scripts/diagnosis_engine.py export-report --input data/diagnosis_report.json --output data/diagnosis_report.md --root .
python scripts/diagnosis_engine.py polish-review --sections-dir sections --consistency data/consistency_map.json --index data/literature_index.json --p1 sections/P1_立项依据.md --ref sections/REF_参考文献.md --json-output data/diagnosis_report.json --md-output data/polish_review_report.md --root .
```

**合并与字数：**
```

python scripts/section_merger.py merge --sections-dir sections --only P1_立项依据.md,P2,REF_参考文献.md --output output/阶段稿_合并.md
```

## 二、各脚本详细职责

### 2.1 state_manager.py（核心调度器）

**职责：** 项目生命周期管理，所有操作的入口。

```
命令清单：
  init            创建项目目录结构 + 空配置文件
  profile         交互式配置 proposal_profile.json
  load            加载状态（支持 --section / --minimal / --global）
  update          更新状态（merge模式，不覆盖未变更字段）
  snapshot        创建快照（sections/ + data/ + *.json 全量备份到 snapshots/）
  rollback        回滚到指定快照（覆盖当前状态）
  word-count      调用 word_counter.py，按节/全文统计
  page-estimate   调用 word_counter.py，按每页~800字估算
  write-cycle     预写门控：
                    1. 加载当前节已有内容摘要
                    2. 注入 consistency_map 关联条目
                    3. 注入文献上下文（仅P1）
                    4. 分配token预算
                    5. 返回组装好的上下文
  self-review     触发 diagnosis_engine.py 执行评审
  sync-all        强制同步检查：
                    遍历 consistency_map / literature_index /
                    context_memory / project_state / history_log
                    任何一项未更新 → 报错并阻断
                  可选 --auto-fix 自动补齐最小骨架并修复轻微结构问题
```

**关键实现细节：**
- `load --section P1 --minimal`：只读取 P1 的 key_facts（≤10条×80字）+ consistency_map 中 source_section 含 P1 的条目
- `load --global`：读取所有节的 key_facts + 完整 consistency_map + literature_index.metadata
- `snapshot` 使用时间戳命名：`snapshots/20260227_143022_phase1_complete/`
- `rollback` 前自动创建当前状态的安全快照

### 2.3 citation_validator.py（文献卫士）

**职责：** 文献真实性验证 + 引用-索引一致性矩阵检查。

```
  verify-all      验证所有文献（支持 --mcp-ttl-days / --manual-review / --log）
  matrix-check    引用-索引一致性矩阵检查
  stats           输出引文统计（总数/近5年/中文期刊）
  find-orphans    查找孤立引用和孤立条目
```

**验证流程（每条文献）：**

```python
def verify_entry(entry, search_tools):
    result = {
        "title_match": None,
        "title_similarity": None,
        "doi_valid": None,
        "pmid_match": None,
        "id_cross_match": None,
        "retracted": None,
        "confidence_score": None,
        "needs_manual_review": None,
        "checked_at": datetime.now().isoformat()
    }

    # Check 1: 标题真实性 — 用DOI或PMID反查
    if entry.get("pmid"):
        pubmed_result = search_tools.search_pubmed(entry["pmid"])
        result["title_match"] = fuzzy_match(entry["title"], pubmed_result["title"])
    elif entry.get("doi"):
        semantic_result = search_tools.search_semantic(f"DOI:{entry['doi']}")
        result["title_match"] = fuzzy_match(entry["title"], semantic_result["title"])

    # Check 2: DOI有效性
    if entry.get("doi"):
        result["doi_valid"] = validate_doi_format(entry["doi"])

    # Check 3: PMID对应性
    if entry.get("pmid") and entry.get("doi"):
        result["pmid_match"] = cross_check_pmid_doi(entry["pmid"], entry["doi"])

    # Check 4: 撤稿检查
    result["retracted"] = check_retraction(entry)

    # Check 5: 正文引用核对（需外部传入P1内容）
    # 在调用层面完成

    # 如果出现 title_mismatch/id_mismatch/mcp_stale/source_unreachable
    # 自动进入 manual_review_queue
    return result
```

**引用矩阵检查：**

```python
def matrix_check(p1_content, literature_index, ref_file):
    issues = []

    # 提取P1中所有[N]引用
    p1_refs = extract_citation_numbers(p1_content)

    # 提取索引中所有条目
    index_refs = {e["ref_number"] for e in literature_index["entries"]
                  if "P1_立项依据" in e.get("used_in_sections", [])}

    # 提取REF文件中的条目
    ref_refs = extract_ref_numbers(ref_file)

    # Check 1: P1引用 → 索引必须有
    orphan_citations = p1_refs - index_refs
    if orphan_citations:
        issues.append(f"孤立引用（正文有但索引无）：{orphan_citations}")

    # Check 2: 索引条目 → P1必须引用
    orphan_entries = index_refs - p1_refs
    if orphan_entries:
        issues.append(f"孤立条目（索引有但正文未引用）：{orphan_entries}")

    # Check 3: REF顺序 = P1首次引用顺序
    p1_order = get_first_citation_order(p1_content)
    ref_order = get_ref_file_order(ref_file)
    if p1_order != ref_order:
        issues.append(f"REF顺序与P1首次引用顺序不一致")

    # Check 4: 三方一致
    if p1_refs != index_refs or p1_refs != ref_refs:
        issues.append("P1引用、索引条目、REF文件三方不一致")

    return issues
```

**节奏检查：**

```python
def rhythm_check(text):
    issues = []
    paragraphs = split_paragraphs(text)

    for i, para in enumerate(paragraphs):
        sentences = split_sentences(para)
        lengths = [len(s) for s in sentences]

        # 检查连续3句长度差异<5字
        for j in range(len(lengths) - 2):
            if max(lengths[j:j+3]) - min(lengths[j:j+3]) < 5:
                issues.append(f"第{i+1}段第{j+1}-{j+3}句节奏单调（长度差异<5字）")

    # 检查段落开头多样性
    openers = [get_opener_type(p) for p in paragraphs]
    for i in range(len(openers) - 1):
        if openers[i] == openers[i+1]:
            issues.append(f"第{i+1}段和第{i+2}段开头结构相同（{openers[i]}）")

    return issues
```

### 2.5 section_merger.py（合并器）

**职责：** 按标书正确顺序合并原子文件为终稿。

```
命令清单：
  merge           合并 sections/ 下全部现场 .md 为单一 md 文件（支持 --only 点名合并；
                  --only 不读结构真源、不做章节校验）
  merge-docx      合并并转换为docx（调用 pandoc，需预装；无 python-docx 回退，缺 pandoc 时返回 "pandoc not found"。Windows 用 choco/scoop 装 pandoc，或在 WSL 里运行）
  validate-order  验证必需章节是否齐全
```

三个子命令都接受 `--root`（缺省 = `--sections-dir` 的父目录，见 §一·补）。

**merge 收全部现场文件，被排除的必须报出来（不静默丢）：**
- 收 `sections/*.md` 全部现场文件——不做"清单外就丢"；有结构真源时不在 `chapters` 里的文件也照收，按文件名数字键排在末尾。
- 只有三类被排除，逐一进输出 JSON 的 `excluded[]`（该键恒存在，没排除时为 `[]`）：
  `not_a_chapter`（排除名单，当前只有 `figure_prompts.md`）/ `p2_parent_present`（`P2_研究内容.md` 与 `P2_x.y_*.md` 同时存在时子文件跳过，防整章重复）/ `empty`（文件存在但内容为空）。
- **`merged_files` 的语义 = 真正进了产物的文件**：空文件不进 `merged_files`，进 `excluded`（reason=empty）。按它核对"一个字不少"不会被空文件骗。
- 无 `--only` 时 merge 先跑 validate-order，缺必需件 exit 2 并列出缺哪些，不产残稿。

**validate-order 的必需件清单来源：**
- 无结构真源：内置国自然清单——12 件必需 + "`P2_研究内容.md` 或任一 `P2_x.y_*` 细粒度原子"，一个不减。
- 有真源且声明了章节表：`required: true` 的 `filename` 集合。
- 有真源、无章节表、`funding_scheme: "other"`：必需件为空（恒通过，结构完全交给用户）；`funding_scheme` 是 nsfc 则仍按内置清单。

**merge-docx 输入格式：** pandoc 调用固定带 `-f markdown+superscript+subscript`，使 md 中 `10^6^`、`H~2~O` 等上下标标注（见 03 §3.5 字符级排版契约）渲染为 docx 真上下标。原子文件必须按该契约标注，否则裸写的上下标在 docx 中丢失。**参考文献角标例外**：正文裸写 `[N]`/`[N,M]`/`[N-M]`（不要写 `^[N]^`，pandoc 会吞掉方括号），pandoc 后由 `_superscript_citations` 后处理统一设上标——它跳过"参考文献"章节及含中文的 `[图1]`/`[表2]`，不误伤列表条目编号与图表号。

**docx 已锁国自然字体**：merge-docx 默认套用 `templates/reference.docx`（`--reference-doc`，存在才加），锁定正文宋体小四（12pt）+ 西文 Times New Roman、各级标题黑体（H1 三号 / H2 小三 / H3 四号）、并显式设 `w:eastAsia` 使中文不回退。模板由 `scripts/make_reference_docx.py` 用 python-docx 改样式生成（字体/字号见脚本顶部常量，幂等）；要改字体改该脚本后重跑即可。

### 2.8 structure_profile.py（结构真源提取链与唯一读口）

**职责：** 非国自然/自定义模板项目的结构声明。项目根的 `structure_profile.json` 是结构真源（章节表 / 顺序 / 必需件 / 字数上限 / 是不是国自然），**只由本脚本的 `confirm` 子命令在用户逐条确认后写入**，别无他路；缺失 = 国自然默认，全部脚本行为与改造前一字不变。四个子命令按「投影 → AI 草案 → 核验 → 用户确认 → 落盘」链路使用（完整流程与 AI 侧五条纪律见 SKILL.md Phase 0「模板结构提取」）：

```
python scripts/structure_profile.py extract-text --source <模板文件> [--work-dir tmp]
python scripts/structure_profile.py verify --draft tmp/structure_draft.json --text tmp/structure_source.txt [--out tmp/structure_candidate.json]
python scripts/structure_profile.py confirm --from tmp/structure_candidate.json --root . [--note "<用户确认原话摘要>"] [--replace]
python scripts/structure_profile.py show [--root .]
```

**extract-text（步骤①，脚本投影）**：把用户原件（.md/.markdown/.txt/.docx/.pdf）投影成纯文本 `tmp/structure_source.txt` + 短行取景框 `tmp/structure_source.lines.tsv`（每行 `<char_offset>\t<行文本>`，只收 1–60 字的行，给 AI 省 token；核验永远针对全文投影，不受取景框限制）。只读原件、绝不写它。docx 按文档顺序遍历段落**和表格单元格**（表格排版的模板也收得全）。stdout 单行 JSON 含 `text_len`（字符数）、`sha256`、`large`（>80000 字符为 true，另在 stderr 提示优先读取景框）。退出码：0 成功；1 源损坏（docx 非 zip / pdf 打不开 / 抽出正文不足 200 utf-8 字节疑扫描件——仅对 .docx/.pdf 判，.md/.txt 不判）；2 用法错（文件不存在 / 扩展名不支持 / 缺 python-docx / 无 PDF 抽取器）。

**AI 草案 `tmp/structure_draft.json`（步骤②，AI 唯一直接写的文件）**形状：

```json
{"source_file": "/path/模板.docx", "funding_scheme": "other", "template_name": "湖南省自然科学基金面上项目2026",
 "chapters": [
   {"title": "一、立项依据与研究内容", "order": 10, "required": true,
    "word_max": 4000, "word_max_evidence": "限4000字"},
   {"title": "二、研究基础与工作条件", "order": 20, "required": true}]}
```

`title` 必须是投影的逐字节连续子串；`word_max` 只在原文明确写了时给且必须带 `word_max_evidence`（同为逐字节子串、其中数字须等于 word_max）；不写 `filename`、不写正文。

**verify（步骤③，防编造闸门）**：逐条核验草案。任一条 `title` 在投影里找不到 / 为空 / 超 200 字 / evidence 对不上或数字不符 → **整批拒收**：exit 3，stdout 打 `STRUCTURE_VERIFY: NOT_IN_SOURCE` 并逐条回显对不上的串，**不写任何文件**（部分落盘会产出"一半核过一半编的"混合物）。`chapters` 空或缺 → exit 3 + `STRUCTURE_VERIFY: EMPTY` + 最小手填样例。全过 → exit 0，写 `tmp/structure_candidate.json`（`confirmed: false`，此时任何消费脚本都不读它），并按固定规则预填 `filename` 且标 `filename_autogen: true`——文件名是脚本猜的，摆给用户时必须明说请其核对/改成 `sections/` 下真实文件名。同一标题在投影出现多次不算失败（取首现 offset，记 `occurrences` 供用户核对——模板"目录+正文"重复是常态）。

**confirm（步骤⑤，全链唯一写 `structure_profile.json` 的地方；🔴 用户逐条确认前 AI 不得运行）**：候选落盘为 `<root>/structure_profile.json`（写入 `confirmed: true` + 确认时间 + `--note` 原话摘要；丢弃 char_offset/occurrences/evidence 等验证痕迹，只存结构）。已存在真源时默认拒绝覆盖：exit 2 + `STRUCTURE_PROFILE: EXISTS`；重提须用户显式要求并加 `--replace`——覆盖前打新旧逐章 diff（`+新增` / `-删除` / `~改名` / `↕顺序变化`），旧版摘要进 `history[]` 不丢数据；若两次源文件 sha256 相同但章节表不同，额外打一行明示"这是 AI 提取的固有波动、不是你的文件被改了"（全链只读原件）。候选损坏/字段非法 → exit 1 + `STRUCTURE_CANDIDATE: INVALID`。

**show（诊断入口）**：文件不存在 → 打内置国自然 13 件（`effective_source: "builtin_nsfc_default"`），exit 0；文件合法 → `effective_source: "file"` + 现算一行 `未提取字段: chapters[i].word_max, ...`（不落盘）；文件损坏/字段非法 → stderr 错误行 + **exit 1**；合法但 `confirmed` ≠ true → stderr UNCONFIRMED 行 + 回落内置默认，exit 0。

**结构真源三态（所有消费脚本同口径）**：文件不存在 = 正常态，走内置国自然默认，**零输出**；损坏 / 字段非法 / 未确认 = stderr 打一行 `STRUCTURE_PROFILE: CORRUPT/INVALID/UNCONFIRMED <路径>` + 一行处置建议，然后**回落内置默认继续跑、不阻断**（merge/gate-check 等调用方退出码不受影响；唯一例外是上面 show 的 exit 1）。

**⚠️ 有意分叉，别"顺手统一"**：本脚本的 docx 投影按文档序递归收表格单元格文字（表格排版模板必需）；`_shared/extract_headings.py` 的 docx 分支不收表格文字（它服务 Polish 拆分链，是共享分发文件，一个字节不动）。两者能力差异是有意的。

### 2.9 dod_project.py（DoD 自检项协商投影）

**职责：** 把 `references/dod_checklist.json` 减去 `<root>/data/dod_selection.json` 里 `disabled[]` 点名的项，写成临时 checklist，喂给 `delegate_review.py pack --checklist`。过滤只发生在 nsfc 侧，共享脚本 `delegate_review.py` 一个字节不动。

```
python scripts/dod_project.py project --root . --gate p1-dod --out tmp/dod_active_p1-dod.json
python scripts/delegate_review.py pack --checklist tmp/dod_active_p1-dod.json --gate p1-dod --files <files>
python scripts/delegate_review.py verify --checklist tmp/dod_active_p1-dod.json --gate p1-dod --return <子代理返回.json> --section P1 --root .
```

**接进盲检的时机与铁律（SKILL.md 三步命令模板第 0 步）**：`data/dod_selection.json` 存在才跑投影；不存在跳过投影，pack/verify 照旧用全量 `references/dod_checklist.json`（行为与协商前一字不变）。跑了投影则 **pack 与 verify 必须同用这份投影产物**——verify 按 checklist 的 items 算应裁决项，pack 用投影、verify 仍拿全量清单，会把被关的项判成「缺漏未裁决」exit 1，把用户卡在他自己关掉的检查上（实测）。

成功时 stdout 单行 JSON：`{"ok": true, "gate": "p1-dod", "out": "<路径>", "total": N, "active": N, "disabled": N}`。退出码：0 成功；1 checklist 或 selection 损坏（selection 损坏时回落"全项都跑"的临时 checklist **仍会写出、可直接用**，退出码 1 只是提醒去修 selection）；2 未知 gate。

**`data/dod_selection.json` 三态**：不存在 = 全项都跑，零输出（= 改造前行为）；损坏 / 字段非法 = stderr 打 `DOD_SELECTION: CORRUPT/INVALID` + 处置行，回落全项都跑（fail-safe 方向是收紧不是放松）。**落盘这份文件必须写 `"confirmed": true` 且先经用户逐条确认**——报告留痕出口（skipped_checks，见07 §七）只认 `confirmed: true` 的文件，未确认的文件关不进留痕；绝不落盘未经用户确认的 selection。被 `disabled` 的每一项同时进各报告出口的 `skipped_checks`（reason: `dod_selection.disabled`）。

🔴 **已知限制（纪律约束，不是机制闸门）**：这份文件**不在门禁写保护清单里**，脚本也不校验「是谁写的」——`confirmed: true` 靠自律，AI 自己写一份就生效。且**可关项无白名单**：不止国自然特有项（如科学问题属性），通用的去 AI / 引文核验 / 字数上限一样关得掉。用户 2026-08-03 拍板「不加机制、只如实登记」——写保护挡不住「用户确认后由 AI 代笔落盘」这条合法路径，现有保护又只认固定路径，真要堵得另起一轮设计。**所以：脚本不拦不等于允许——没有用户逐条确认，绝不落盘这份文件。**

**职责：** 整合所有检查器，生成结构化诊断报告。
