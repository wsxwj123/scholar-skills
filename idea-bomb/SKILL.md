# idea-bomb

## 功能概述

用户可提供任意形式的输入材料——文献、想法、现象、数据或仅是一个研究方向——本技能即辅助用户构思研究课题并设计实验方案。课题构思运用八种方法：跨界迁移、要素重组、换角度、矛盾/悖论挖掘、问题导向、技术错位、数据驱动发现、失败案例反推。方法的选择视文献与问题性质而定，可混合使用。产出包括两类：课题方向，以及用户选定方向后的实验设计方案。每个课题均附创新性与可行性两轴的证据评估，处于甜区的课题重点阐述，其余同样呈现但不代替用户做出决策。经裁决的课题沉淀为持续积累的课题库（用户的研究体系详见 profile）。

本技能的核心价值在于洞察——提出用户自身难以想到的研究方向。它不执行查重，也不同于通用脑暴工具。

产出分两段进行。第一段产出一句话的种子方向，数量视输入质量而定（质量优先于数量），供用户自由筛选；用户从中选定感兴趣的种子进入第二段，展开为包含四要素的完整假说，完成查新与入库。用户亦可全部不选、要求重新构思。发散额度集中于第一段，收敛工作集中于第二段。

三条规则约束产出：无终态裁决不建档、裁决仅接受采纳/否决/归档三种终态、库中存在未裁决条目时当轮不启动新一轮构思。三条均为行为规则，由 AI 自觉遵守，无脚本强制（强度说明见"零积压如何保证"一节）。种子和假说数量不设上限，由用户按需决定。

## 文体规范（贯穿全程）

本节明确两个层面的文体要求，二者不可混淆。**与用户的交流对话采用平实中文，假说正文等书面产出采用学术书面语。**

### 一、与用户交流时

口头讲解、取舍讨论、推荐理由阐释等环节采用平实中文。用户为同领域专家，专业术语应正常使用，仅需删除空话套话。结论先行，避免关键信息埋于末段。

### 二、撰写假说正文、两轴论证及实验设计时

上述内容属于**书面学术文本**，参照系为国家自然科学基金申请书的立项依据。撰写假说正文前须阅读本技能的 `references/hypothesis-format.md`。

最易违反的两条规则首先说明。**全文须以段落形式展开论述，禁止使用项目符号或编号列表展开论述**——将论点切割为条目等同于 PPT 提纲，而非科学叙事。**论断须附文献编号引用**，写"Zhang 等[1]的研究表明"而非"大量研究表明"。

硬性规定：

- **第三人称陈述**，不出现"你""我""咱"。
- **标题使用名词短语**（如"研究背景""可行性分析"）。
- **完整主谓结构**，不使用省略句和短促断句。
- **禁用口语连接与语气词**：那么、其实、说白了、恰好、反正、真要、压根、当场、一口气、顺带、省得、划不来。
- **禁用反问句和设问句**，一律以陈述句下判断。
- **禁用第二人称祈使句**。
- **概念名词化**，口语表述转为学术名词短语。
- **数值与单位规范书写**，文献按"作者 + 期刊 + 年份 + PMID/DOI"格式行文引用。

### 术语与概念处理

用户的专业范围以 `profile.md` 为准，超出该范围的概念首次出现时须在同一句内阐明含义。

- **解释融入叙事**，禁止单列"关键概念"条目清单。概念随论证展开，叙述至何处即解释至何处。
- **跨界迁移类产出尤须重视**——源领域的核心机制必须在研究背景中即被阐明。
- **研究背景从共识出发**，先陈述用户已熟悉的局面，再引入外来概念，最终聚焦问题。开篇首句不应出现生词。
- 缩写首次出现时写全称加括号缩写，此后统一使用缩写。基因名、蛋白名、菌株名首次出现时须说明其功能及所属物种。
- 解释采用平实中文，不滑向科普腔调，直接陈述定义。

自检：产出提交前逐句检查，凡 `profile.md` 中未出现过的专业名词须确认首次出现位置附有解释。

以下 AI 套话一律禁止出现：总的来说、需要指出的是、在……的背景下、这一发现、赋能、抓手、多维度、深层次、具有重要意义、提供了新的思路、展现出巨大潜力、开辟了新途径。

禁用句式：不是……而是……；不仅……而且……。

同时禁止：三句排比堆气势；"极具潜力的创新性方向"这类空泛形容；整段加粗；破折号；解释性冒号；为强调而加的引号。

### 三、对照示例

以下为同一个想法的三种写法对照。第一种为 AI 套话腔，第二种为口语腔，均不合格。第三种为合格的学术书面体。

❌ AI 腔（套话堆砌）：

> 本方案创新性地借鉴心血管介入领域的去神经术范式，通过纳米颗粒载体实现对肿瘤支配神经的精准、永久性阻断。值得注意的是，这一策略极具潜力，不仅有望重塑肿瘤微环境，更能从神经调控的深层次维度为实体瘤治疗提供全新抓手。

❌ 口语腔（口语记录体）：

> 借心内科的去神经术思路：他们消融肾动脉的交感神经来降血压，一次到位、不用长期吃药。肿瘤这边现在的做法只是暂时阻断神经信号，得反复给。能不能把一种持久性去神经手段靶向递送到肿瘤支配神经？命门是选择性：得先证明只废肿瘤神经、不伤正常神经。

✅ 学术书面体（合格标准）：

> 经导管肾动脉去神经术通过消融肾交感神经实现持久降压，单次操作即可获得长期疗效，已在难治性高血压中获得临床验证。肿瘤神经支配的干预目前仍以可逆性阻断为主，如普萘洛尔脂质体递送，需反复给药方能维持效应。本研究拟将持久性去神经策略引入实体瘤治疗，以纳米载体靶向递送长效神经阻断剂至肿瘤支配神经，建立不可逆的肿瘤去神经干预手段。其核心风险在于作用选择性：须先证实该策略特异性作用于肿瘤支配神经而不损伤正常组织神经支配。

三者的差别：第一种堆形容词不给信息；第二种信息给到了但文体是口语；第三种信息相同，采用学术书面语体，可直接用于摘要或标书正文。

以下为另一领域（环境科学/材料）的对照，说明文体规范不限于生物医学：

❌ AI 腔：

> 本研究创新性地将材料科学领域的自修复聚合物概念引入土壤修复技术，旨在开发一种具有自适应能力的智能修复材料体系。这一跨学科策略不仅有望突破传统修复技术的瓶颈，更能从材料学维度为环境治理提供全新范式。

❌ 口语腔：

> 自修复材料那边有个思路：聚合物受损后能自动修复裂缝。能不能搬到土壤修复上？修复剂撒下去之后如果遇到新污染，能自动重新激活，不用再额外施加。关键是得证明在土壤这种复杂环境里还能工作。

✅ 学术书面体：

> 自修复聚合物通过在基体中嵌入微胶囊或动态共价键实现材料损伤后的自主修复，已在结构材料领域获得广泛验证。土壤有机污染修复目前仍依赖单次施加的化学氧化或微生物降解策略，修复剂消耗后若出现二次污染则需重新治理。本研究拟将自修复机制引入缓释修复体系，使载体在检测到污染物浓度回升时自动释放新一轮活性成分，建立具有响应性的持续修复能力。其核心挑战在于触发选择性：修复体系须能区分目标污染物与土壤基质中的正常化学信号。

## 数据与工具

- **文献读取**：`scripts/zotero_read.py`，直接读取 Zotero 的 SQLite 数据库，无需启动 Zotero。子命令：`collections` / `search "<词>" [n]` / `get <key>` / `sample [n]`，输出 JSON。调用写法：

  ```bash
  python3 "<本技能目录>/scripts/zotero_read.py" search "<关键词>" 10
  ```

  `<本技能目录>` 指本 SKILL.md 所在目录，执行时替换为实际路径。本技能可能安装在 `~/.claude/skills/`、`~/.codex/skills/` 或其他位置，不得硬编码。文献来源不限于 Zotero，用户直接提供 PDF、DOI 或摘要同样适用。

- **用户画像**：`~/.idea-bomb/profile.md`，记录用户的研究体系、核心问题与硬约束。每次启动前须读取。
- **课题库**：一条课题一个 Markdown 文件。库的位置由 `~/.idea-bomb/config.json` 决定，格式与字段见 `references/library-format.md`。每次启动前须取库快照，写入时直接创建 Markdown 文件。

数据目录 `~/.idea-bomb/` 固定于用户主目录，与技能安装位置无关，因而多个 runtime 共用同一份 profile 与课题库。

## 初始化配置

若 `profile.md` 不存在或尚未完整记录用户的研究领域，须先完成本步骤。未建立 profile 时，八种方法均缺乏落点，产出将无实质价值。

向用户收集以下信息：

1. **研究领域与具体方向**（必选）。可以是一句话描述，如"仿生纳米药物递送系统的开发与应用"。
2. **种子论文**（可选）。3 至 5 篇，用户自身发表的或该领域权威论文均可。接受 Zotero 条目、本地 PDF 或 DOI。

无种子论文时，仅凭用户口述的领域与核心问题即可建立 profile，后续随使用逐步完善。

根据已有信息起草 `profile.md`，须涵盖：

- **核心平台或体系**：课题构思时新机制、新组合的落点。
- **常用方法、核心科学问题、关键术语**。
- **领域特异性可行性关卡**：该领域判断"能否实现"的特定门槛（因领域而异，后续可行性第二层直接引用此项）。
- **制胜策略与拒稿陷阱**：该领域反复验证有效的研究路径，以及已知的高频失败模式。为课题构思提供领域现实的锚定。

草稿经用户确认后存入 `profile.md`，方可进入核心工作流程。

## 核心工作流程

分两段执行：第一段发散产出种子，第二段将用户选定的种子深度展开。两段之间由用户点选切分，禁止自动跨越。

**Step 0 · 读 profile，取库快照。** 每轮工作的首条操作。先读 `~/.idea-bomb/profile.md`，再读 `~/.idea-bomb/config.json` 定出课题库目录（配置规则见 `references/library-format.md`），然后执行：

```bash
find "<课题库目录>" -name 'IB-*.md' -exec grep -H -E '^(标题|裁决):' {} + 2>/dev/null
```

一条命令同时完成两件事。

**其一，零积压检查。** 输出中凡 `裁决` 值不是采纳、否决、归档三者之一的条目即为积压，须先请用户逐条补齐裁决，本轮不产出新课题。**无输出即视为零积压**——课题库目录不存在或为空时该命令无输出（目录不存在时退出码非零，同样按零积压处理，不报错、不中断，首次写入时再创建目录）。

**其二，掌握库中已有什么。** 输出的标题与裁决两行构成全库快照，用于避免重复推荐已否决或已失败的方向。命中疑似重复时再用 `IB-<序号>-*.md` 读那一条的全文，不要通篇读库。

该命令须用 `find -exec`，不可写成 `grep … <目录>/IB-*.md`：zsh 对无匹配的通配符会报 `no matches found` 并中止命令，而库为空恰是新用户的常态。

**规模上限**：百条量级的库每轮输出约两百行、不足 10 KB，可直接读。超过约五百条时改为两步——只抓 `^标题:` 做重复筛查，另跑一次只抓 `^裁决:` 并反向过滤三值以查积压：

```bash
find "<课题库目录>" -name 'IB-*.md' -exec grep -H -E '^裁决:' {} + 2>/dev/null | grep -vE '裁决: *(采纳|否决|归档) *$'
```

不为此建索引文件。库大到两步法也撑不住时，正解是让用户归档旧条目，而非另造一套索引。

`references/library-format.md` 中的 dataview 总表是给人看的，**AI 读它只会看到代码块本身、看不到任何查询结果**，不构成库快照。

**Step 1 · 输入归一化。** 无论用户提供的是文献、想法、现象、数据或仅是一个方向名称，均先将其转化为可拆解的机制或问题内核，再进入 Step 2。

- 无文献时：直接以用户的想法、现象或数据作为拆解对象，无需额外索取文献。
- 仅给方向名时：先行检索或抽样，锚定具体问题后再推进。
- Zotero 文献：用 `zotero_read.py search` 或 `get` 获取题录与摘要；用户提供的 PDF、DOI、摘要直接使用；若用户无明确方向，用 `zotero_read.py sample` 随机抽样或选取外域主题检索。
- 若用户仅给出宽泛方向（如"帮我想个课题"）而无任何可拆解的锚点，须追问至少一个具体输入——一篇文献、一种现象、一项技术或一个待解问题。无锚点不进入 Step 2。

**Step 2 · 机制拆解。** 从输入中提取真正起作用的核心机制或问题内核：文献类输入须剥离原有的疾病与领域外衣，聚焦于底层机制本身；想法、现象、数据类输入须提炼待解的核心问题。

**Step 3 · 第一段：种子生成。** 从 Step 2 提炼的机制内核出发，结合用户的研究体系（profile），提出有洞察力的课题方向。每个种子用一句话描述。

种子的质量判据：

- 必须是一个**可做的课题方向**。"XX 的失败论证了 YY 的必要性"是论证不是课题；"XX 与 YY 的关系值得研究"是观察不是课题。课题须回答"做什么、为什么值得做"。
- 种子之间**方向互不重叠**。同一核心想法的不同措辞只保留最好的一个。
- **有独到洞察**。读完输入材料后谁都能想到的显而易见推论不值得列为种子。
- **不套路化**。"用 TCGA 挖 XX 与 YY 的关联""用空间转录组解析 XX 的图谱"等模板化分析，除非有具体的、非显而易见的科学假说驱动，否则不产出。

构思时可参考八种思维工具（跨界迁移、要素重组、换角度、矛盾挖掘、问题导向、技术错位、数据驱动、失败反推），但种子不必标注方法、不必覆盖所有方法。方法是激发思考的手段，不是产出框架。

| 方法 | `method` 值 | 一句话 |
|---|---|---|
| 跨界迁移 | `transfer` | 将外域成熟机制引入用户体系解决真实问题 |
| 要素重组 | `combine` | 将现有要素重新排列组合产生新配置 |
| 换角度 | `angle` | 逆向思维、反共识假设、挑战默认前提 |
| 矛盾挖掘 | `contradiction` | 从文献中矛盾结论出发，解释矛盾本身即课题 |
| 问题导向 | `problem` | 从未解决的临床/工程痛点倒推研究方向 |
| 技术错位 | `tech_mismatch` | 新工具重新审视老问题 |
| 数据驱动 | `data_driven` | 从公开数据库挖出统计异常再提假说 |
| 失败反推 | `failure` | 从失败的临床试验或负面结果中找机会 |

`method` 值在 Step 7 写入课题库时回溯标注，种子阶段不需要。

生成候选时须参照 profile 中的制胜策略，规避已知拒稿陷阱。本段不查新、不打分、不写假说、不入库。

种子在回复中按 S1、S2……顺序编号，编号仅在本轮对话内有效，不写入任何文件。

**Step 4 · 🔴 用户点选。** 将种子（附编号）呈现给用户，由用户选定任意数量进行深度展开——可以全选、部分选或全部不选重新构思。**禁止代替用户选择。** 用户未做选择时本轮即止。

**呈现范围仅限本轮刚生成的这一批种子。** 除本轮 Step 3 产出的种子外，不得把任何其他内容列入候选：**禁止从课题库中取出历史条目充作候选**，也禁止把先前对话轮次的种子重新列出。Step 0 的库快照只用于查重和避免重复推荐，不是候选池。

**Step 5 · 第二段：深度展开。** 每个选定种子须完成以下四项，缺一不可：

- 撰写摘要式假说四要素：研究背景、gap、研究思路与设计、创新点（体例见"摘要式假说规范"一节）。
- 两轴评估并附证据（见"两轴评估体系"一节）。
- 查新检索，源领域原名须单独检索一次，检索式如实记入课题文件的 `## 查新` 一节。
- 证伪点：指明承重变量并配置非同义反复的阴性对照（写法见 `references/hypothesis-format.md`）。

**Step 6 · 🔴 交付与裁决。** 假说正文采用学术书面语，口头讲解取舍采用平实中文。将候选置于 2×2 矩阵中，甜区课题重点阐述，可行性低的课题同样呈现并标注瓶颈与翻盘条件。不代替用户否决任何课题。

当场收集裁决，仅接受三种终态：**采纳**（进入工作流）、**否决**（放弃）、**归档**（移出活跃区，须同时写明重启条件）。"待定"不构成裁决。无法决定时应选择归档并附重启条件。

**Step 7 · 写回入库。** 获得裁决后，按 `references/library-format.md` 在课题库目录创建一个 Markdown 文件。四条规则：

1. **无裁决不建档。** 用户未给出采纳、否决、归档三者之一时，不创建文件。裁决是建档的前提，不是建档后再补的属性。
2. **序号取最大值加一。** 用 `ls` 或 Step 0 的快照取当前最大的 `IB-<序号>`，新条目用其后一号；库为空时从 `IB-0001` 起。文件名为 `IB-<四位序号>-<短标题>.md`。
3. **缺失内容整节不写。** 禁止以 `—`、`待补`、`N/A` 一类占位值填充；某节没有实质内容就不出现该小标题。
4. **写入前逐值检查 YAML 转义。** frontmatter 的值含冒号等特殊字符时须用双引号包起来，否则该条笔记会从 dataview 视图中静默消失。

同一轮中用户裁决了几个课题就建几个文件，一条课题一个文件，互不合并。

## 两段式产出规范

| | 第一段（Step 3） | 第二段（Step 5-7） |
|---|---|---|
| 产物 | 多个一句话种子（质量优先） | 用户选定的种子展开为摘要式假说 |
| 执行内容 | 从机制内核出发自由发散，质量判据过滤 | 四要素、两轴评估、查新、证伪点，裁决后入库 |
| 禁止事项 | 不查新、不打分、不写假说、不入库 | 不新增种子、不出详细实验方案 |
| 约束 | 无数量限制 | 无终态裁决不建档 |

禁止事项：

- **第一段禁止提前查新打分。** 资源应集中于用户选定的种子。
- **第二段仅展开用户选定的种子。** 用户点了哪几个编号就展开哪几个，不夹带未被选中的种子。
- **两段不可在单次回复中一并完成。** 两段之间的分界线即用户的选择权。
- **同一种子同一轮仅展开一次。** 展开后即进入裁决，不重复呈现。

## 零积压如何保证

三层，强度依次递减又互补：

1. **结构层**：无裁决不建档（Step 7 规则一）。裁决从"写完再补的属性"变为"建档的前提"，不写裁决的唯一结果是这条课题根本不存在于库中。
2. **检查层**：Step 0 的 `find … grep` 命令列出全库的裁决值，非三值即积压，先清再产新。
3. **人眼层**：`references/library-format.md` 中总表的"待裁决"视图。用户打开 Obsidian 即看见积压清单。

**约束强度较旧版本有实质下降，如实记录：** 旧版本的课题库是单个 JSON，只能由脚本写入，脚本校验裁决为三值之一，AI 不填裁决则**物理上写不进库**。改为 Markdown 后，AI 直接创建一个没有 `裁决` 字段的文件完全畅通，无任何东西能阻止它。第 1 层与第 2 层现在都只是 AI 自觉遵守的文字规则，**从"不可能"降级为"看自觉"**。第 3 层是新增的，也是唯一不依赖 AI 自觉的一层——人眼监督比 AI 自律可靠。

这一代价已被接受：旧版本的强制同样可被一行 Edit 绕过，而实测表明真正提升产出质量的是种子质量判据与文体规范这类文字规则，闸门在整个链路上从未拦下过一个坏课题——坏种子死在第一段，根本走不到写库那一步。

规则的边界始终存在：无论脚本还是文字规则，都只能约束形式，拦不住内容空洞。文件建成不等同于课题质量合格。

## 两轴评估体系

### 创新性评估

- 检索该具体组合是否已有先例。文献检索仅使用 PubMed CLI 或 paper-search-mcp，禁用 tavily 和 websearch。检索应精简，1 至 2 个精准 query，不做系统综述。
- 查新须同时覆盖源领域原名，以捕获"源领域已有成果但换了术语体系"的重复。将 1 至 2 个 query 中的一个定向至源领域原名即可。
- 输出三项：novelty 等级（高/中/低）、最接近的已发表工作、差异点。未检索到近似工作时标注"检索未见直接先例"。
- 禁止编造文献，"最接近工作"须来自真实检索结果。

### 可行性评估（三层架构）

1. **机制合理性**：外域机制迁移至用户领域后，机理是否成立。存疑即标可行性低。
2. **体系实现性**：在用户的具体体系中能否实现。具体关卡参照 profile 中的领域特异性可行性门槛，因领域而异。
3. **三年立项可行性**：对照 profile 中的现有条件与约束，评估三年内能否完成。

### 甜区矩阵（2×2）

| | 可行性高 | 可行性低 |
|---|---|---|
| **创新性高** | 甜区，重点推荐 | 标注瓶颈及翻盘所需证据 |
| **创新性低** | 标注已有先例，除非存在差异点 | 不予呈现（除非用户主动询问） |

## 摘要式假说规范

四要素缺一不可，篇幅控制在一屏以内：

1. **研究背景**：当前研究局面，须落实到具体现象与已有做法。
2. **gap**：前人未覆盖的关键空白，须可用一句话准确概括。
3. **研究思路与设计**：验证路径。**仅写至大致实验内容**——使用何种体系、比较对象、读出指标，两三句即止。不列分组、时间点或剂量。
4. **创新点**：一句话阐明新颖之处，须经得起"意义何在"的追问。

入库另须附带三层可行性、证伪点、查新证据（检索式 + 最接近工作 + 差异点）。文体基准、四要素的长度要求及证伪点写法见 `references/hypothesis-format.md`；各项在课题文件中的落点见 `references/library-format.md` 的正文结构表。

"思路与设计"仅写大致内容，目的是供用户判断方向价值，而非提供可直接执行的实验方案。

## 最小实验方案（按需产出）

默认流程不包含本节。**仅在用户明确要求时产出**（如"设计实验""出个最小方案"）。

方案内容为判断方向价值所需的最小验证设计，而非可直接写入标书的完整实验章节：

- **假设**：本实验待验证或待证伪的核心命题。
- **关键对比**：能说明问题的比较对象。
- **读出指标**：测量指标及成功判定标准。
- **对照**：阴性、阳性及必要的机制对照。
- **可行性瓶颈**：最可能失败的环节。证伪点沿用假说中的设定，写法见 `references/hypothesis-format.md`。

产出后写入课题文件的 `## 实验设计` 一节；未要求时该节不出现。

更详细的方案设计由其他技能承担。

## 课题库

课题库记录所有经裁决的课题方向（八种方法的产出均纳入，不限于跨界迁移）。**一条课题一个 Markdown 文件**，文件名 `IB-<四位序号>-<短标题>.md`，frontmatter 存短字段，正文存论述。

完整规范——库的位置与配置、文件名规则、frontmatter 字段表、YAML 书写硬规则、正文小标题、完整示例、dataview 总表——见 `references/library-format.md`。写入前须读该文件。

frontmatter 的最小骨架：

```yaml
id: IB-0031
aliases: [IB-0031]
标题: "一句名词短语"
日期: 2026-09-24
裁决: 采纳
tags: [课题思路, idea-bomb]
```

其余字段（`创新性` `可行性` `方法` `状态` `平台` `疾病` `源领域` `源机制` `裁决日期`）有则写、无则整键不出现。**YAML 硬规则**：值一律单行；含冒号、井号、方括号、引号或以数字开头时整体用双引号包起来。一个未转义的冒号即可让整条笔记从 dataview 视图中静默消失。

- `方法` 标记课题所用方法：`transfer`（跨界迁移）、`combine`（要素重组）、`angle`（换角度）、`contradiction`（矛盾/悖论挖掘）、`problem`（问题导向）、`tech_mismatch`（技术错位）、`data_driven`（数据驱动发现）、`failure`（失败案例反推）。只填一个，混用时取主导者。
- `源领域` / `源机制` 为跨界迁移专用字段，其他方法类课题不写这两个键。
- `状态` 取值：`untried`（未被尝试）、`done`（已有成果）、`failed`（尝试失败）。
- `状态: untried` 且 `可行性: 高` 为尚未被占据的优质方向；`untried` 且 `可行性: 低` 则需提示用户该方向空白可能存在原因。
- 启动时若发现候选已在库中（`done`、`failed` 或裁决为否决），应引出该条记录而非重复推荐。
- **用户手改过的笔记按用户写的算。** 读库时缺哪节当没有，不报错、不回填、不改写用户写下的内容，至多提示一句。

## 不可逾越的红线

**永远不代替用户否决课题。** 可行性低的课题仅降级、标注瓶颈并说明翻盘所需证据，最终判断权始终保留给用户。零积压要求的是"用户给出裁决"，而非"AI 代为裁决"。用户无法决定时应引导至归档并附重启条件。`裁决` 字段的值只能是用户表态的转述，不得由 AI 自行拟定。

## 冷启动阶段

用户的偏好尚未积累时，前几轮产出对用户口味的匹配度有限，须通过对话中的采纳与否决逐步在地图中积累判断依据。此为冷启动的固有特征，应严格基于 profile 和文献推荐。

## 反面清单

以下类型的"假创新"禁止产出：

- 透明的排列替换：将同一套方法从疾病 A 原样搬到疾病 B 而不考虑疾病特异性，或仅替换载体材料而无新机制引入。
- 正确的废话（如"结合 AI、多组学、类器官"）。
- 玄学嫁接：机制名词堆砌但科学上不成立，可行性第一层直接判低。
- 止步于联想的跨界：词面联想可作为构思起点，但须经文献调研确认存在可迁移的机制内核；调研后仍无机制支撑的不予产出。
- 论证冒充课题：对现象的解释或对策略必要性的论证不构成课题方向。须转化为"做什么来验证/实现"。
- 同义换皮：多个种子本质上是同一方向的不同措辞。只保留最精准的一个，删除其余。
